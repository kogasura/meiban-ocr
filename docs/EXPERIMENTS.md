# 実験台帳 — 棄却された手法と確定した知見

「成功しない方法の発見」も成果として記録する。新しい施策を検討する前にここを読むこと。
数値は held-out (serial-disjoint) の clean test / E2E 実測 (eval_end_to_end.py)。

## 偽発火の後段フィルタ (全て実測で弱い、300枚 quad@1280)

偽発火の正体 = 実在シリアルの 1-3 文字誤読 (背景からの捏造はゼロ)。

| フィルタ | 実測 | なぜ効かない |
|---|---|---|
| フレーム内多数決 | 票なし (発火box は銘板あたり~1個) | フレーム内に冗長性がない |
| フレーム間合意 (2回/窓5) | 偽-37%、正-9pt | 偽読みの63.7%は再出現 (同条件→同誤読の systematic) |
| sequence conf gate | correct 0.975 vs false 0.967 | ほぼ重なる |
| min文字 conf gate | @0.9 で偽-31%/正-4.4% | 自信満々に誤る (false med 0.991) |
| 単純DB存在照合 | 92%すり抜け | 連番ロットでは誤読が隣の実在シリアルに着地 |

→ 根本解は (a) 誤読自体を減らす (b) アプリ側の期待集合照合+件数整合。

## デコーダ変更系は3敗で打ち止め

fixed-head / CTC チューニング / attention の3系統が全て pos11 を動かせなかった。
末尾2桁の弱さは「視覚特徴そのものの曖昧さ」(encoder/入力側) と確定。
→ その後、入力側アプローチの **末尾 2nd-pass が初めて pos11 を動かした** (勝ち手参照)。

## 末尾 2nd-pass の4反復で踏んだ落とし穴 (06-11)

| 反復 | 構成 | fixed:broken | 教訓 |
|---|---|---|---|
| 1 | セル推定・品質ゲートなし | 121:673 | tail訓練データのラベルノイズ。だが修正可能量121件を実証 |
| 2 | +MMアンカーゲート | 10:0 | ノイズは消えるが、ゲートが難crop=修正対象の43%を棄却 (catch-22) |
| 3 | CTCアライメント位置特定 (被覆99%) | 38:477 | 読み手の訓練分布 (deskew帯crop) と評価分布 (生ストリップ) の不一致 |
| 4 | + 訓練データも同じ作り方 (分布一致) | 111:45 | 採用。位置特定と訓練データは必ず同じパイプラインで作る |

他の前提: full モデル (v10) は reject 訓練の副作用で部分シリアルを全列 blank と読むため、
2nd-pass には部分 crop で訓練した専用モデルが必須。

追補 (06-11): tail モデルの tiny arch 化 (3MB) は**棄却** — tail 単体 EM 88.7 (VGG版 92.8)
の差が統合で「自信を持った誤置換」になり全閾値 net 悪化 (最良 fixed29:broken74)。
2nd-pass の読み手は full 側より高精度であることが必須条件。配信は VGG 版 fp32 (33MB、
内部配信のためサイズはソフト制約)。INT8 量子化は未着手の課題。
